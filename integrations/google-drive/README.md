# FC shared content — Google Drive pilot

This is an **unconnected pilot**, not a released integration. The owner approved public text explanations and protected FC playback. No paid resources are required by this implementation; Apps Script quotas and reliability still need a live pilot. A Drive/Google One storage subscription does not buy OpenAI usage or unlimited Apps Script execution.

## Implemented and tested locally

- `/content-manager`: bilingual editorial interface, search, new themes, recording registration, preview, draft save, explicit human review, atomic publish, withdrawal, and session logout. Existing catalog metadata is available for review; existing LearnWorlds descriptions are not silently republished.
- `/library/:id`: public, reviewed explanation in Chinese or English with approved testimonial sources and real FC membership playback links. Audio is never hosted here or made public by this feature.
- An authenticated private Drive gateway, using only `drive.file` and outbound HTTP scopes. A dedicated app-created private folder/file stores content. No all-Drive scope, file-sharing changes, customer audio, intake answers, medication or other customer health records.
- Revision checks and Apps Script `ScriptLock` prevent concurrent editors from overwriting a newer version. A request ID and content digest make an immediate repeated write idempotent. Unknown write outcomes require a fresh read before another edit; there is no blind automatic write retry.
- AI refreshes the same published feed on publication and at most every 15 minutes on ordinary use. Content has a real publication date plus a separate generation/check timestamp, so unchanged explanations do not expire merely because they were edited more than a week ago. Failed checks still expire the cached feed after seven days.
- The public reader does not disclose drafts, prior versions, administrator credentials or the Drive file ID. Plain text is rendered with DOM text nodes, not injected HTML. The owner reviews both language versions and the source/recording mapping before publication.

## Owner setup — not completed

1. Review `Code.gs` and `appsscript.json` in a **new standalone Apps Script project owned by the FC owner**. The manifest enables Drive v3 on the default Google Cloud project and requests only per-app-file access plus outbound HTTP. It preserves default exception logging; request bodies and credentials are never logged by the code.
2. The owner must authorize these scopes. Do not bypass a security warning or expand to all-Drive access. Account/app approval is a separate explicit step; code upload is not proof that the connection is authorized.
3. The owner/IT securely configures a high-entropy `FC_GATEWAY_TOKEN` (at least 32 characters) in Script Properties, then runs `initializePrivateContentStore`. Never paste the credential into chat, a URL, repository or browser bundle. Setup creates private app files and saves their IDs in Script Properties. A rare partial setup failure can leave an empty private folder/file; inspect before any cleanup.
4. Review and deploy this as a web app running as owner, accessible to backend requests. Although the endpoint can receive anonymous HTTP requests, its `doPost` rejects every read/write without the server token. There is no public `doGet`. **This new owner-executed endpoint and its persistent credential require explicit authorization before deployment.**
5. Configure backend-only `FC_DRIVE_GATEWAY_URL` (the exact `/macros/s/.../exec` URL) and `FC_DRIVE_GATEWAY_TOKEN`. Keep `FC_CONTENT_SESSION_SECRET` (32+ random characters) and `FC_CONTENT_ADMIN_PASSWORD_HASH` (scrypt `salt:hex`) separate. The password hash is generated using `passwordHash` in `routes/content.js`; actual password entry/configuration belongs to the owner/IT. Do not commit any values. The editor uses HttpOnly/Secure/SameSite=Strict cookies and CSRF checks. It is intentionally opened as a separate page rather than inside an iframe.
6. Log into the editor and initialize the current FC catalog once. Initialization refuses a nonempty store. Preserve existing explanation pages while importing/reviewing their content. No draft is automatically considered reviewed.
7. Validate live addition, modification, withdrawal, concurrent edits, failed reads, service restart, and the exact returned public and AI source text. Verify the quota/account behavior of the actual Google account. Test the real provider, recording microphone, member identity and usage persistence separately before requesting any production release.

## Local preview

Set `FC_CONTENT_TEST_FILE` to an absolute private file outside the repo, `FC_CONTENT_TEST_ORIGIN` to the exact loopback URL, and the editor secret/password hash. The local file implementation is **single-process preview only** and is deliberately disabled on Render. A visible notice identifies local storage; test publication updates the local reader and local AI source only.

## Boundaries and remaining work

- This connection is for **editorial content**, not a live membership verifier or transactional customer-usage database. Formal member allowances and durable usage reservations remain separate release gates. Do not change the existing usage guard to trust a browser-selected subscription.
- LearnWorlds API is unavailable on the current plan. Uploading an audio file in LearnWorlds alone cannot automatically register it here. The new content manager is the shared registration point: add the actual course/player URL and a human-confirmed version once, then publish its explanation for both readers and AI.
- Current source/feed limits: 600 theme families, 30 recordings per family, twelve bilingual snippets of 1,400 characters each, 20 testimonial sources. The private document is capped at 2.8 MB, gateway response at 3 MB and validated AI feed at 2 MB. Exceeding a limit fails closed; it never truncates the entire store or resets it. Measure the migrated content before release; large long-form articles/media need a separate per-article store and validated references rather than silently dropping paragraphs. The current three-field editor is for concise purpose, usage and care information, not a lossless long-form article importer.
- Original full articles, studies and media must remain on FC until a full long-form migration is reviewed. One-time source capture is private, unreviewed migration material; no scraped text or testimonial is automatically approved. The snapshot and new recording metadata do not establish clinical effectiveness.
- The bounded history stores up to twelve recent publication/withdrawal records. Restore puts the most recent prior published text into a private draft; it never publishes automatically. An authenticated export downloads the content store, including drafts, without credentials or customer intake data. This manual export is not an independent automatic backup. Agree and verify a regular backup plan before relying on this as the sole production source.
- Google quota exhaustion, expired authorization or gateway failure stops editing; the public viewer reports unavailability, and the AI falls back to its dated catalog after cache expiry. No guarantee of production uptime or zero additional future cost is made.
